# Proof-of-Work Portfolio & Deployed Project

**Weight:** 15% · **Live URL due:** Session 4 (Wed 10/28) · **Final due:** Session 14 (Wed 12/9, demo day)

## Why

Anyone can generate a project with AI now, so a GitHub repo alone says less than it used to. What still stands out to hiring managers:

- A project that's **actually live** and works
- Evidence of **judgment**: why you built it this way, what tradeoffs you made, what you'd change
- Evidence of **quality**: tests, error handling, a clear README
- Proof that **you** understand it: you can explain and extend it on the spot

This assignment makes sure you leave the course with at least one project that does all of that.

## Requirements

### 1. One proof-of-work project, deployed

Pick your strongest existing project (or one you'll finish during the term). It must:

- [ ] Be live at a public URL by **Session 4** (see the [Deployment Guide](../Resources/Deployment_Guide.md) for free options)
- [ ] Have at least a few meaningful automated tests
- [ ] Handle obvious errors (bad input, network failures) gracefully
- [ ] Not commit any secrets (API keys, passwords)

If your best project truly can't be deployed (for example, a native mobile app), link a 2-minute demo video at the top of the README and talk with the instructor.

### 2. A README that sells the project

- [ ] One-sentence description of what it does and who it's for
- [ ] Live URL and screenshot or GIF at the top
- [ ] Tech stack
- [ ] How to run it locally
- [ ] What you'd build next
- [ ] An **AI Use** section: which tools you used and for what (see [disclosure guidance](../Resources/AI_In_The_Job_Search.md#6-disclosure-when-and-how-to-tell-employers-you-used-ai))

### 3. A decisions write-up (`DECISIONS.md`)

A short document (about one page) covering 3–5 real decisions you made. For each one:

- What you decided (e.g. "Used Postgres instead of MongoDB")
- What alternatives you considered
- Why you chose this one
- What you'd do differently now

This is the document that sets you apart. It's also your script for "walk me through a project you're proud of."

### 4. GitHub profile

- [ ] Profile photo and short bio with what you're looking for
- [ ] Profile README (optional but recommended)
- [ ] 3–6 pinned repos, with your proof-of-work project first
- [ ] Every pinned repo has a description and a README — no empty or "class assignment" repos pinned
- [ ] Repo names are descriptive (not `project-2-final-v3`)

### 5. Personal site (optional)

A simple site linking your projects, resume, and contact info. Can be your GitHub Pages site.

## Demo day (Session 14)

You'll give a 5-minute demo of your project: 2 minutes showing it live, 3 minutes walking through one decision from `DECISIONS.md`. Classmates and the instructor will ask follow-up questions, just like an interviewer would.
